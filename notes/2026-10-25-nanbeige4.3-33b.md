# Nanbeige4.3-33B on my Mac mini

Date: 2026-10-25

[Nanbeige4.3-33B](https://huggingface.co/Nanbeige/Nanbeige4.3-33B) is a 33B open-weight model from the Nanbeige team. There was no MLX build yet, so I made a 4-bit one and benchmarked it on my Mac mini. All credit for the model goes to Nanbeige. The license is Apache 2.0.

## The build

MLX affine quantization, 4-bit, group size 64. That's about 4.5 bits per weight once you count the scales and biases, and 18.6 GB on disk. Every linear layer is quantized, including the embeddings and `lm_head`. I used mlx 0.32.4 and mlx-lm 0.32.2 (the same math as `mlx_lm.convert -q`).

The build is on Hugging Face at [pratikgx/Nanbeige4.3-33B-MLX-4bit](https://huggingface.co/pratikgx/Nanbeige4.3-33B-MLX-4bit). To run it:

```bash
pip install mlx-lm
mlx_lm.chat --model pratikgx/Nanbeige4.3-33B-MLX-4bit
```

The chat template opens a `<think>` block, so it reasons before it answers. Give it enough `--max-tokens` for both.

## The setup

Mac mini, Apple M5 Pro, 64 GB, macOS 27.0.1, plugged in. No thermal or performance warnings were recorded.

## How I measured

- **Speed:** greedy decoding, 256 generated tokens per test, 1 warmup and then 3 runs. Each number is the median run. Prompts of 512, 4K, 16K and 32K tokens. 512 and 4K were run with thinking on and off. 16K and 32K only with thinking on.
- **Peak memory:** MLX's own peak memory reading.
- **Quality:** small sanity sets I wrote for this (20 math word problems, 10 coding tasks, 10 instruction-following prompts), thinking on, run once. They're sanity checks, not a leaderboard score.
- **Needle in a haystack:** one fact hidden at different depths of a long prompt, at 32K, 64K and 128K, thinking on, run once.

| Quality check | Score |
| --- | --- |
| Math word problems | 20/20 |
| Coding tasks | 10/10 |

It found the needle in all 9 tries: 5 depths at 32K, 3 at 64K and 1 at 128K. Peak memory was 26.35 GB at 32K, 33.44 GB at 64K and 47.75 GB at 128K. The 128K prompt was 131,008 tokens, prefilled at 136.4 tok/s, and took about 16 minutes end to end without running out of memory on 64 GB.

## Caveats

- One machine, one session. Speeds are medians of 3. Quality and needle tests ran once.
- My own harness on top of mlx-lm, not an official eval suite.
- The copy I benchmarked was converted on the Mac (Metal). The uploaded copy was converted on CPU from the same BF16 weights with the same settings. Tensor names, shapes and config match. In a spot check of one full layer, about 0.2% of the 4-bit codes differed by one or two steps from floating-point rounding, and both copies had the same error against the BF16 original.
